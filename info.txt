================================================================================
                    ARCHITECTURE COMPLÈTE PROJET ML - GUIDE DE RÉFÉRENCE
================================================================================

Ce document décrit l'architecture complète du projet de prédiction de churn bancaire
pour vous permettre de reproduire la même structure avec un thème différent.

================================================================================
                            1. VUE D'ENSEMBLE DE L'ARCHITECTURE
================================================================================

Type de projet : Application complète de Machine Learning avec déploiement MLOps
Pattern architectural : Microservices avec Frontend/Backend séparés
Thème actuel : Prédiction de churn bancaire
Adaptabilité : Structure générique pour tout projet de classification

                            3. ARCHITECTURE BACKEND (FASTAPI)
================================================================================

3.1 STRUCTURE PRINCIPALE
------------------------
Framework : FastAPI 0.104+
Serveur : Uvicorn
Port : 8000
Pattern : API RESTful

3.2 COMPOSANTS API
------------------
Fichier : app.py
├── Imports essentiels :
│   ├── FastAPI, HTTPException, UploadFile, File
│   ├── CORSMiddleware (pour communication frontend)
│   ├── BaseModel (Pydantic pour validation)
│   ├── pandas, joblib, io, os
├── Configuration CORS :
│   ├── allow_origins=["*"] (adapter pour production)
│   ├── allow_credentials=True
│   ├── allow_methods=["*"]
│   └── allow_headers=["*"]
├── Chargement modèle :
│   ├── MODEL_PATH = "data/best_model_pipeline.pkl"
│   ├── Vérification existence fichier
│   └── Chargement avec joblib.load()
├── Modèles de données Pydantic :
│   └── CustomerData (adapter selon votre thème)
├── Endpoints :
│   ├── GET /health : Vérification état API et modèle
│   └── POST /predict : Prédiction principale

================================================================================
                            5. ARCHITECTURE INFRASTRUCTURE (DOCKER)
================================================================================

5.1 DOCKER COMPOSE - 3 SERVICES
--------------------------------
version: '3.8'

services:
  backend:
    build:
      context: .
      dockerfile: Dockerfile.backend
    ports:
      - "8000:8000"
    environment:
      - PORT=8000
      - MLFLOW_TRACKING_URI=http://mlflow:5000
    volumes:
      - ./data:/app/data
    depends_on:
      - mlflow

  mlflow:
    image: ghcr.io/mlflow/mlflow
    container_name: mlflow_server
    ports:
      - "5000:5000"
    environment:
      - MLFLOW_BACKEND_STORE_URI=sqlite:///mlflow.db
      - MLFLOW_DEFAULT_ARTIFACT_ROOT=/app/artifacts
    volumes:
      - ./mlruns:/app/artifacts
    command: >
      mlflow server --backend-store-uri sqlite:///mlflow.db 
      --default-artifact-root /app/artifacts --host 0.0.0.0

  frontend:
    build:
      context: .
      dockerfile: Dockerfile.frontend
    ports:
      - "5173:80"
    depends_on:
      - backend

5.2 DOCKERFILE BACKEND
----------------------
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY code/ ./code/
COPY data/ ./data/

EXPOSE 8000

CMD ["uvicorn", "code.app:app", "--host", "0.0.0.0", "--port", "8000"]

5.3 DOCKERFILE FRONTEND
-----------------------
# Build stage
FROM node:18-alpine as build

WORKDIR /app
COPY frontend/package*.json ./
RUN npm ci --only=production

COPY frontend/ .
RUN npm run build

# Production stage
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/nginx.conf

EXPOSE 80

CMD ["nginx", "-g", "daemon off;"]

================================================================================
                            10. RÉSUMÉ TECHNIQUE
================================================================================

Architecture : Microservices Backend/Frontend + MLflow
Backend : FastAPI + Python ML ecosystem
Frontend : React + Vite + Axios
Infrastructure : Docker + Docker Compose
Tracking : MLflow avec SQLite
Database : SQLite pour MLflow, fichiers pour modèles
Deployment : Containers orchestrés
Scalability : Horizontale via containers
Monitoring : Health checks + MLflow UI

Cette architecture est générique et s'adapte à tout projet de Machine Learning
avec des besoins de déploiement en production. Le pattern microservices assure
la scalabilité et la maintenabilité du système.
